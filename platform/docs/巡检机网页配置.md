# 巡检机单机测试：网页配置

本次提供的网络地址：电脑Wi-Fi `10.248.240.249`，巡检遥控器 `10.248.240.25`。这些是本次地址，网络变化后重新核对。

## 新版入口

更新后需要先重启平台服务一次，使服务端加载新代码；之后改接收端口不用控制台命令。页面顶部新增“连接与接口设置”。若提示接口不存在，说明仍在运行旧版服务。关闭网页不会重启服务。

1. 角色选“巡检机”，接收状态“启用”。
2. UDP端口填14550，遥控器IPv4填10.248.240.25。此项是来源过滤，不是电脑地址；留空时允许任意来源。
3. 电脑Wi-Fi IPv4填10.248.240.249，仅用来生成QGC填写提示，不会修改Windows网卡。
4. 保存并应用。遥控器QGC的MAVLink forwarding目标填写 `10.248.240.249:14550`。本平台不能替你修改遥控器上的QGC。
5. 切换角色为“灭火机”，选“停用”，保存。这样不会占用灭火机UDP端口，界面仍保留该机卡片。

修改到空闲新端口时立即生效；新端口被占用时保留原配置与原接收，不强行终止其他程序。端口切换/来源修改会清空该通道当前遥测，等待新数据，避免显示旧飞机数据。配置保存在data/state.json，重启后保留。启动脚本显式传入端口参数时该次启动优先使用参数；普通启动使用保存配置。

## 视频地址

“原始RTSP视频源”目前只是配置记录，不启动媒体服务或识别进程；不要把它当成已接入功能。需要确认电脑确实能播放的共享视频地址后填写，不能仅把遥控器IP拼成某个猜测地址。只知道两端同一Wi-Fi不能保证摄像机网络可达。

各视频栏原有“接入设置”仍设置系统编号和HTTP/HTTPS播放器网页地址。它与RTSP源不同，仍需视频中转服务。

## 识别项目

后续已读取桌面general_detection项目：其README和weights/provenance.json表明该模型为COCO通用检测，没有火焰/烟雾类别（fire hydrant是消防栓，不是火）。入口live.py还依赖缺失的同级fire_smoke_weights/live_usb_detection.py。未运行自动火点识别或上传。电脑已通过nvidia-smi确认RTX3050Ti Laptop GPU、4GB显存，i5-12500H、16GB RAM；实际视频处理性能仍需测试。

## 外部局域网的视频链路

目标是电脑与遥控器共同连接路由器/手机热点，不通过遥控器热点、USB或网线直连。此时遥测QGC转发可以独立配置，但视频需遥控器在其局域网IP开放中转服务，或有经过验证的路由方案。只填写C12内部地址不能创建网络路径。原厂G12手册第13节列的是遥控器热点、以太网络共享和USB网络共享，并不能据此断言外部Wi-Fi客户端模式也支持直接访问摄像机。

待确认遥控器是否已有局域网视频转发能力；否则需要额外遥控器转发组件。其监听端口与RTSP路径尚未确定，不提供假定已可用的视频地址。网页原始视频源目前只存储配置。
